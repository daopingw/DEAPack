This protocol preserves a classic congestion account without converting an
incomplete book preview into a public estimator. Congestion is a transferable
management question. The Färe--Grosskopf--Lovell formulation remains a named
technical route within that question, not a separate handbook model family.

## 1. Defining sources and access boundary

The defining lineage is Rolf Färe and Shawna Grosskopf, “Measuring Congestion
in Production,” and Rolf Färe, Shawna Grosskopf, and C. A. Knox Lovell,
*The Measurement of Efficiency of Production* (1985). See the
[original chapter record](https://doi.org/10.1007/978-1-349-07123-4_6) and the
[official book record](https://link.springer.com/book/10.1007/978-94-015-7721-2).
The [scanned-book preview](https://books.google.com/books?id=OaWffSMcV14C&pg=PA69&vq=congestion)
exposes only part of the required pages.

The audited pages support the following source-level statements:

- absence of input congestion is tied to strong input disposability;
- the source congestion component is
  $C_1(u,x)=W_1(u,x)/F_1(u,x)$, with $0<C_1\leq 1$ and the neutral value one;
- the broader constant-returns account includes
  $K_1(u,x)=S_1(u,x)C_1(u,x)F_1(u,x)$; and
- the strong-disposability activity set displayed on page 75 can be read from
  the preview.

The preview truncates the complete weak-disposability construction around
page 74. It also does not expose the complete data needed to reconstruct the
chapter's numerical table. These omissions prevent a compilable source freeze.
The accessible [1984 application abstract](https://doi.org/10.1287/mnsc.30.6.671)
corroborates the pure-technical, congestion, and scale distinction, but it
cannot replace the defining technology and numerical example.

## 2. Economic claim that is currently supported

Ordinary input redundancy and congestion are not synonyms. A redundant input
can be reduced while the represented output commitment is maintained.
Congestion makes the stronger claim that excessive input use suppresses what
the organization can attain, so releasing the obstructing input can unlock
output. In the Färe--Grosskopf--Lovell route this claim is identified by a
comparison involving different maintained input-disposability technologies.

That mechanism is not an ordinary CCR/BCC post-processing label. It is also
not an environmental bad-output weak-disposability model, a by-production FGL
index, a capacity-utilization measure, or a generic input-slack diagnosis.
These boundaries may be taught conceptually. No source-attributed programme,
score, target, or variable-level congestion attribution is currently
authorized.

## 3. Items not yet source-frozen

Implementation remains blocked until the source settles:

1. the complete weak input-disposability production set and every variable
   domain in the defining programme;
2. the exact relationship between the weak and strong technologies, including
   constraint directions and scaling variables;
3. the returns-to-scale domain of each component and its relationship to the
   conical example;
4. the native directions and interpretation of $F_1$, $W_1$, $C_1$, $S_1$,
   and $K_1$;
5. the full observations and expected values in Tables 3-1 and 3-2; and
6. a production-free LP compiler or exact independent analytical certificate.

Two visible congestion values from a partial table are not an oracle when the
underlying data and full defining programme are unavailable.

## 4. Handbook and package disposition

The active book may explain the management distinction between idle resources
and resources that impede production inside the existing scale chapter. It
must not publish an “FGL congestion model” section, equation recipe, package
example, named-variant table, or independent chapter from this incomplete
record.

`analysis.congestion.fgl_1985` is an internal audit locator only. It is absent
from the executable registry, public imports, API Documentation, and teaching
cases. Directional, environmental, network, and application-specific
congestion formulations do not inherit readiness from this protocol.

## 5. Gate for a later version

Reopen this candidate only after:

1. an authorized complete copy of the relevant 1985 pages, including Chapters
   3 and 8 dependencies, is available for a page-level audit;
2. the weak and strong technologies and every component identity are frozen;
3. the full source example is transcribed and independently reproduced for at
   least one neutral and one congested activity;
4. the identity $K_1=S_1C_1F_1$ and score directions are independently checked;
5. solver failures, nonunique projections, reference matching, and any input
   partition receive explicit contracts; and
6. any eventual material is absorbed into the scale family rather than used
   to create a paper-named handbook route.

Until then, `deferred_to_next_version` is the release disposition.

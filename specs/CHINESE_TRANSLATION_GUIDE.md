# DEAPack Handbook 中文术语与翻译规范

**状态：** 简体中文版 Handbook 的规范性编辑约定；须在批量翻译章节前冻结术语。

**适用范围：** 仅适用于配套 Handbook。2.0 版本线的包 Documentation、API
reference、docstring、源代码和公开结果模式仍只使用英文。本规范已经用于 28 个
Handbook 正文 gettext catalog、1 个主题界面 catalog 与 52 幅中文图，后续修订仍须遵守同一约束。

**配套文件：**

- 机器可检索术语表：[terminology/dea_zh_terms.tsv](terminology/dea_zh_terms.tsv)
- 逐源翻译风险审计：[HANDBOOK_CHINESE_TRANSLATION_AUDIT.md](HANDBOOK_CHINESE_TRANSLATION_AUDIT.md)
- 规范符号系统：[CONVENTIONS.md](CONVENTIONS.md)

## 1. 编辑目标

中文版应当像一本直接写给中文经济学、管理学、政策分析和相关专业学生的书，而不是把
英文句法逐字搬到中文里。同时，中文版必须完整保持英文版的模型契约。

总原则是：

> 翻译经济与管理含义；保持数学、计算、证据和书目身份不变。

具体而言，中文版首先要回答：一个组织控制哪些资源、承担哪些产品或服务责任、哪些
比较对象具有可比性，以及拟合技术能够支持什么改进。几何只在确有助于解决技术问题时
出现。因此，方向性距离函数首先是一套预先声明的联合改进方案，而不是一支箭头；生产率
分解首先区分经营表现变化与生产机会变化，而不是描述两条线如何移动。

## 2. 权威来源与冲突处理

术语决策遵循以下证据层级：

1. 中文经典专著、经过正式审校的中文译著，以及国际机构手册的正式中文版；
2. 中文经济学、管理科学、统计学、运筹学和资源环境领域权威期刊论文。优先使用期刊
   官方页面、DOI 页面或出版社 PDF，不以聚合搜索结果代替原始来源；
3. 方法的英文定义文献，尤其用于避免中文译法改变数学对象，例如混淆 *indicator*
   与 *index*；
4. 当前英文 Handbook 与 `specs/CONVENTIONS.md`；二者决定本项目的概念、符号、
   得分方向、代码标识和模型边界。

术语不能靠搜索结果“多数表决”。若中文文献中存在多个稳定译法，本规范选择最能保持
经济含义的一种作为主词，把其他译法记录为可检索别名，并禁止同一章来回换用。

`book/_archive/` 下的旧中文草稿和 `book/locale/` 下尚未审定的 PO catalog 都不是
权威来源。只有在逐句对照当前英文源、本规范和术语表之后，才可把它们作为 translation
memory 参考。不得按旧目录整章复制：旧路线更短、结构已经过时，而且不少段落采用本版
已经明确放弃的几何优先叙述。

## 3. 中文叙述方式

### 3.1 从经济与管理问题出发

优先采用以下表达：

- “在既定服务责任下，医院能够节约多少可控资源？”
- “污染削减目标与合意产出增长目标共同构成这一改进方案。”
- “共同前沿把组内管理无效率与组间生产机会差距分开。”
- “该得分是在指定参照技术和比较对象下得到的条件性标杆结果。”

在读者理解经济问题之前，不要把“从原点作射线”“沿箭头移动”“两条前沿的距离”
作为主要解释。只有当图示或推导确实需要时，才在后文使用这些几何表达。

### 3.2 不得强化证据

DEA 给出的是相对于已声明技术和比较总体的绩效判断。翻译不得把证据说得更强。

- `supports` 或 `is consistent with` 不能强化为“证明”或“导致”；
- 模型支持的目标不是管理命令、预测或因果处方；
- 活跃参照单元不自动等于其实践可以照搬的组织；
- 效率变化分量不能诊断绩效变化的原因；
- 群组技术差距不自动由政策、所有制或地理位置造成。

### 3.3 能说具体组织时，不反复说“DMU”

首次出现写“决策单元（decision-making unit，DMU）”。案例给出具体对象后，优先写
医院、工厂、银行、学校、地区或营业网点。只有一般性讨论或公式确需抽象时才继续使用
“DMU”。绝不能把 DMU 译为“决策者”，因为被评价单元未必是作出决策的人。

## 4. 冻结的核心术语

TSV 是完整的机器可检索契约。下表列出正文编辑中最容易漂移的决策。

| 英文概念 | Handbook 规定用语 | 编辑边界 |
|---|---|---|
| efficiency / productivity | 效率 / 生产率 | “生产力”不是本书所度量的定量 productivity 指标。 |
| technical / allocative efficiency | 技术效率 / 配置效率 | Farrell 意义的配置效率需要价格信息和成本、收益或利润目标；不能把一般性的资源配置结论都称为 AE。 |
| input-/output-oriented | 投入导向 / 产出导向 | “输入/输出导向”是正式译法之一，但不作为本书经济学行文的主词。 |
| returns to scale | 规模报酬 | “规模收益”是稳定别名；constant returns 绝不能译成“固定规模”。 |
| production possibility set | 生产可能集 | 接受“生产可能性集”，但同一章不得交替使用。 |
| directional distance function | 方向性距离函数（DDF） | “方向距离函数”作为检索别名。方向是一套有单位的既定改进方案，不只是一支箭头。 |
| slacks-based measure | 基于松弛变量的效率测度（SBM） | 英文原名是 *Slacks-Based Measure*，不是 “Slack-Based Model”。优化变量写“松弛变量”，已报告缺口写“松弛量”。 |
| desirable / undesirable output | 合意产出 / 非合意产出 | “期望产出/非期望产出”是重要稳定译法。一章只能使用一组完整配对，不能混写“合意/非期望”。“坏产出”“负产出”“负面产出”都不是正式模型术语。 |
| Malmquist productivity index | Malmquist 生产率指数 | 人名保留拉丁字母，避免并存的多套音译。 |
| Luenberger productivity indicator | Luenberger 生产率指标 | 这是加法 *indicator*；不能不加区分地全部改称“指数”。 |
| efficiency change / catch-up | 技术效率变化（EC）/追赶效应 | EC 是正式分量名。“追赶效应”是解释性用语，可能为正也可能为负；未核对数值和方向前不能写成已经成功追赶。 |
| technical change / frontier shift | 技术变动（TC）/前沿移动效应 | TC 是中性名称。只有数值与约定表明生产机会扩张时，才写“技术进步”。 |
| network DEA | 网络数据包络分析；网络 DEA | 若可能与 DEA 后接回归的 two-stage procedure 混淆，“两阶段网络 DEA”必须保留“网络”。 |
| dynamic DEA | 动态数据包络分析；动态 DEA | 只有生产技术用状态/结转变量显式连接时期，才称动态 DEA；面板、窗口或 Malmquist 比较本身不等于动态 DEA。 |
| carry-over | 结转变量（跨期联结变量） | 要解释从本期进入下期并约束未来生产机会的经济状态。 |
| metafrontier | 共同前沿（metafrontier，亦称元前沿） | 正文使用“共同前沿”，“元前沿”保留为索引别名。 |
| technology gap ratio | 技术差距比（TGR） | 比较群组与共同生产机会，不是未解释残差，也不自动是因果环境效应。 |

### 4.1 非合意产出的成对用语

中文文献存在两套均有依据的传统。“合意/非合意”直接表达产出增加是否受到偏好，
“期望/非期望”则在中文 DEA 应用研究中广泛使用。本书选择“合意产出/非合意产出”，
因为它不会让读者误解为统计意义上的期望或意外。首次实质性出现时写：

> 合意产出与非合意产出（undesirable output；中文文献亦常称“期望产出/非期望产出”）

说明这一别名后，本章只使用规定配对。搜索词、glossary 和 index 必须同时收录两套
传统。已有代码标识仍为 `output`、`bad_output` 和 `undesirable_outputs`；中文
选词不构成 API 重命名。

### 4.2 生产率分解

先使用中性分量名，再解释符号：

- `EC` 或 `TEC`：技术效率变化；可在括号中补充“追赶效应”；
- `TC`：技术变动；可在括号中补充“前沿移动效应”。

只有核对具体指数约定以后，才能说“大于 1 表示改善”。“技术进步”是正向技术变动
分量的一种结果解释，不是这个分量无条件的名称。同样，当组织相对参照技术进一步落后时，
不能仍写成正在“追赶”。

生产率方法中的 `global` 指以所声明时期共同构造参照技术，应译为“全局”而不是
“全球”。它是一项参照政策，不是地理概念。

### 4.3 距离函数与 DDF 方向

“距离函数”是相对于可行生产技术定义的函数，不是普通欧氏几何距离。投入和产出距离
函数应分别通过资源压缩与服务/产品扩张来引入。

DDF 的方向向量规定“一单位改进”由什么构成：投入节约、合意产出扩张、负担削减，
或者事先声明的组合。方向具有单位，也体现改进优先级。它不是价格向量，不能独立产生
配置效率。

### 4.4 标杆、参照单元、投影与目标

必须区分以下对象：

- **参考集**：拟合表示中强度为正的观测集合，并服从具体方法的报告约定；
- **活跃参照单元**：拟合强度非零的个体观测；只有定义清楚后才可简称 “peer”；
- **标杆方案**：对模型支持的比较方案所作的管理学描述；
- **投影**：数学上得到的投影活动；
- **目标方案**：在已声明目标选择器下报告的可行目标。

这些对象都不能自动识别可移植实践或因果干预。存在 eligibility restriction 时，
必须区分“候选比较对象”“合格比较对象”和“活跃参照单元”，不能一律写成“标杆”。

### 4.5 网络、动态与共同前沿账户

网络 DEA 通过表示内部过程和中间产品来“打开黑箱”。联结变量必须保留其供应过程与
接收过程的双重角色。过程结果是在特定系统技术下作出的会计归属，不必然对应某位管理者
的唯一责任。

动态 DEA 通过结转变量表示本期决策如何约束未来生产机会。结转类别要按经济角色翻译，
不能只看正负号：合意存量、非合意积压、可自由调整的联结和固定承诺分别形成不同的跨期
契约。

共同前沿账户把相对于群组自身机会的绩效与群组和共同机会之间的差距分开。已知群组不是
模型自动推断的聚类。

## 5. 首次出现格式与排版

### 5.1 默认格式

术语首次实质性出现时采用：

> 中文推荐译法（English term，ABBREVIATION）

例如：

- 决策单元（decision-making unit，DMU）
- 方向性距离函数（directional distance function，DDF）
- 基于松弛变量的效率测度（slacks-based measure，SBM）
- 技术差距比（technology gap ratio，TGR）

专名已经保留拉丁字母时，不要机械重复音译。“Malmquist 生产率指数（Malmquist
productivity index）”已经足够。首次出现后，稳定使用中文主词或既定缩写。同一章
不反复展开 DEA、DMU、CRS、VRS、DDF 或 SBM。

### 5.2 中文标点与拉丁对象

中文句子使用全角标点。拉丁字母/数字与中文之间在有助可读性时保留一个普通 ASCII
空格，例如“DEA 模型”“Python 实现”“2 个时期”。Farrell、Charnes、Cooper、
Rhodes、Banker、Malmquist、Luenberger、Hicks 和 Moorsteen 等专名保留拉丁字母，
除非所引用的正式中文书目已经给出规范译名。

## 6. 不得翻译的对象

下列对象承载身份。除非英文源本身改变，否则必须保持字节或 token 身份不变：

- Python import、包、模块、类、函数、方法、参数、枚举值、dataset ID、列名、
  result field、exception 和代码输出标签；
- 公开 method ID、preset ID、registry ID、CLI 命令、文件路径、URL 与环境变量；
- 数学符号、索引字母、上下标、集合、算子、约束、不等号方向和得分公式；
- MyST/Sphinx directive 名、`:name:` 等选项、显式 label、`{doc}` 与 `{numref}`
  target、citation key 和 BibTeX key；
- `references.bib` 中原文作者名和文献标题。

数学 `\text{...}` 命令内可见的解释性文字可以翻译，但周围公式必须接受 token 级
比较和渲染审查。结果列不能只因为作为表头出现就翻译；若它是 package 的字面字段，
应使用 code font 并保留英文标识。

只有当代码注释面向读者、且不会改变 doctest、预期输出或可复制示例时，才可翻译。
第一版采用保守政策：代码注释原则上不动，把中文解释写在代码块周围的正文中。

## 7. 图、表、参考文献与链接

图注和 alternative text 应当翻译；文件路径、directive `:name:` 与交叉引用 target
不得改变。Sphinx gettext 不会处理 SVG 内嵌英文。本项目使用显式审校标签目录和
确定性本地化器生成中文资产；英文源 SVG 的 SHA-256 一旦改变，构建便停止并要求重新
审校。若下次构图会覆盖修改，绝不能只手工编辑生成后的 SVG。

表格中的概念性表头可以翻译，字面 API/result field 则以 code font 保留。数值精度、
单位、缺失值标识和脚注作用范围都不得改变。

Citation key 与书目记录不变，只翻译讨论文献的句子。不得编造中文题名、版次、出版社、
DOI、ISBN、页码或译者信息。引用正式出版的中文译本时，应把译者和版次作为独立书目记录。

可见标题改变后，自动生成 anchor 也可能改变。需要跨版本或外部稳定引用的标题，应在
翻译前使用显式 label。

## 8. 翻译流程与验收门槛

翻译按受控批次推进，顺序见风险审计。

1. 由双语领域专家审查并冻结本规范、TSV、`book/notation.md` 和
   `book/glossary.md`；
2. 翻译前言、导读和基础章节，校准中文叙述方式；
3. 先翻经典模型，再翻环境与生产率账户，因为后两者依赖前者的得分与技术约定；
4. 内部流、跨期状态和群组技术术语稳定后，再翻网络、动态和共同前沿章节；
5. 用 community-hospital 案例作端到端可复现性和风格验收。

每个批次必须通过以下全部门槛：

- 中文 Sphinx HTML 严格构建，warning 视为 error；
- 中文 PDF 构建，并目视检查 CJK 字体、书签、断行、数学和 metadata；
- 按 `dea_zh_terms.tsv` 执行术语 lint，包括禁止混搭的术语配对；
- 对公式执行 token 比较，并双语复核已翻译的 `\text{...}`；
- 验证代码块和输出字段身份，再执行可运行示例；
- 检查 citation key、显式 label、`{doc}` 与 `{numref}` 完整性；
- 检查图注、alt text 以及 SVG `<text>`、`<title>`、`<desc>`；
- 专门审读几何优先表达、因果强化以及把条件性目标误写成处方的问题。

仅仅因为每个 gettext message 都有非空译文，不能把一章视为“已完成”。

## 10. 变更控制

主词发生任何变化，都必须在同一个 pull request 中同时更新本规范与 TSV。变更说明必须
指出它是语义变化、纯排版变化还是新增别名，提供可核验来源，并列出受影响章节。仅凭
出现频次不足以支持变更。

英文 Handbook 仍是内容权威。英文模型契约变化后，应先更新术语和审计，再重新生成中文
catalog。若中文表达暴露英文源歧义，应先修订和复核英文源，不能把歧义隐藏在译文中。
